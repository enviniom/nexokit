# HTTP Middleware Specification

## Purpose
Define the middleware stack: RequestID, Recovery, CORS, and Logger, including execution order.

## Requirements

### Requirement: RequestID middleware

The system MUST generate a UUID request ID when the `X-Request-ID` header is absent and propagate it to the response header.

#### Scenario: Missing request ID

- GIVEN a request without `X-Request-ID`
- WHEN it passes through the middleware
- THEN the response contains `X-Request-ID` with a generated UUID

#### Scenario: Existing request ID

- GIVEN a request with `X-Request-ID: abc-123`
- WHEN it passes through the middleware
- THEN the response contains `X-Request-ID: abc-123`

### Requirement: Recovery middleware

The system MUST recover from panics in handlers, return HTTP 500 with the standard error envelope, and log the panic details.

#### Scenario: Handler panic

- GIVEN a handler that calls `panic("boom")`
- WHEN a request hits that handler
- THEN the client receives 500
- AND the standard envelope shows `success: false`
- AND the server process remains alive

### Requirement: CORS middleware

The system MUST enforce CORS policy using `CORS_ALLOWED_ORIGINS` from config.

#### Scenario: Allowed origin

- GIVEN `CORS_ALLOWED_ORIGINS=http://localhost:3000`
- WHEN a preflight request arrives from `http://localhost:3000`
- THEN CORS headers are present and the request is allowed

#### Scenario: Disallowed origin

- GIVEN `CORS_ALLOWED_ORIGINS=http://localhost:3000`
- WHEN a request arrives from `http://evil.com`
- THEN CORS headers deny the origin

### Requirement: Logger middleware

The system MUST log every request with method, path, status code, duration, and request ID.

#### Scenario: Successful request

- GIVEN a GET request to `/health`
- WHEN it completes with 200
- THEN the log line contains `method=GET`, `path=/health`, `status=200`, `duration>0`, and `request_id`

### Requirement: Middleware order

The system MUST apply middleware in this order: RequestID → Logger → Recovery → CORS.

#### Scenario: Panic with request ID

- GIVEN a handler that panics
- WHEN the request is processed
- THEN the recovery log line includes the same `request_id` generated by RequestID middleware

## Constraints and Edge Cases

- Recovery MUST catch panics in middleware that runs after it.
- Logger MUST not leak request bodies or query parameters containing passwords.
- CORS MUST handle preflight (`OPTIONS`) requests correctly.
